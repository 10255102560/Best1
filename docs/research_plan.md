# 基于精确策略梯度的预算感知 Harness 自改进：研究计划

本项目研究一个有限、可复现的问题：在基础语言模型、提示词和可选执行流程均固定的条件下，能否根据任务特征，用 CPU 上的小型梯度优化器改进执行路线选择，使数学题的准确率与 token 开销取得更好的权衡？

研究对象是 **Harness 层的参数自改进**。实验不训练或微调基础模型，不自动编写新的工具，也不声称实现开放式递归智能提升。以下内容记录已经冻结的实验方案与解释规则，不预设任何正向结果。配置以 `artifacts/gsm8k_flash_v1/config.json` 为准，结果应另见实验报告。

## 1. 问题选择与研究假设

| 候选问题 | 可观察现象 | 可优化对象 | 本次处理方式 |
| --- | --- | --- | --- |
| 过度推理 | 简单题也产生较长计算说明，增加输出 token | 是否要求显式步骤 | 设置 `direct` 与 `reason` 两条路线 |
| 盲目检查 | 无条件复核花费额外调用，且可能把正确初稿改错 | 是否执行第二次检查 | 设置 `review`，统计修好与改错次数 |
| 静态路由 | 所有题都采用同一流程，无法利用任务间差异 | 基于题目特征的路线选择 | 作为本次主要优化问题 |

主要假设是：不同路线在不同题目上的收益存在差异，而且题目中可直接提取的特征能预测其中一部分差异。若某条固定路线几乎全面占优，或者特征无法预测路线优劣，学习路由器可能没有收益。这是允许出现的研究结论。

`direct` 的含义是仅要求最终答案，`reason` 的含义是要求简洁计算步骤。实验只控制可见提示词，不能据此断言模型内部完全没有隐式推理。模型由用户提供的 API 暴露为 `deepseek-v4.1-flash`；实验只能验证该接口返回的行为，不对服务端权重或模型身份作独立认证。

## 2. Harness 与真实反馈

固定三条执行路线：

1. `direct`：一次请求，要求直接返回最终数值答案。
2. `reason`：一次请求，要求简洁计算过程及最终答案。
3. `review`：先生成与 `reason` 相同的初稿，再用第二次请求检查解释、算术和目标量，允许保留或修正答案。

参考答案只用于本地评测，不进入模型请求或路由特征。答案使用显式标记提取与严格数值比较，不调用额外 LLM 裁判。格式错误、未输出有效答案或结果错误都计为失败，同时单独报告格式失败与输出截断次数。

为减少采集开销，同一题的 `review` 复用已经取得的 `reason` 初稿，因此实际采集每题只需三次请求。评估 `review` 部署成本时，仍累加初稿和检查两个步骤的输入 token、输出 token、请求数与耗时。共享初稿是有意采用的配对设计；三个动作不是三个独立任务样本。

这是全动作反馈实验：每道采集题都会测量所有路线，构成实际观测的奖励矩阵。当前策略并不控制探索数据的采样分布；改进发生在路线参数层，属于受限的评测反馈闭环，而非自主发现新流程的开放式 RSI。

## 3. 梯度方法与目标函数

### 3.1 仅训练 48 个路由参数

每道题从问题文本提取 15 个固定特征：字符数、词数、数值数量、最大数值、句子数的对数尺度特征，问号数，加减乘除、百分数、顺序、金额、比较类词汇特征，以及小数数量。特征不读取答案、任务 ID、数据集划分或路线输出。

设标准化特征为 $x_i\in\mathbb{R}^{15}$，权重矩阵为 $W\in\mathbb{R}^{15\times3}$，偏置为 $b\in\mathbb{R}^{3}$：

$$
z_i=x_i^\top W+b,\qquad
\pi_\theta(a\mid x_i)=\frac{\exp z_{ia}}{\sum_{k=1}^3\exp z_{ik}}.
$$

一共优化 $15\times3+3=48$ 个参数。标准化只使用训练题。候选从当前已接纳版本暖启动：已接纳版本的标准化参数保持不变；如果现任尚未拟合标准化器，新候选使用当轮累计训练集估计标准化参数。验证与测试数据只用于预测，不用于拟合标准化器。

### 3.2 准确率与 token 的预先固定权衡

对于任务 $i$ 和动作 $a$，定义：

$$
r_{ia}=\mathbb{1}\{\text{答案正确}\}-0.05\frac{T_{ia}}{1000},
$$

其中 $T_{ia}$ 为 API 报告的路线总 token。`review` 包含两步总和。输入与输出 token 在本次目标中等权；它是计算开销代理指标，不能直接换算为人民币费用，也不能代表所有供应商的实际计费规则。

该权重表示平均每题多花 1000 token，要获得超过 5 个百分点的准确率提升，才能使平均效用上升。准确率和 token 必须分别报告，避免仅用单一效用分数掩盖质量下降。

训练使用以下平滑目标：

$$
J(W,b)=\frac1N\sum_{i=1}^N\left[
\sum_a\pi_{ia}r_{ia}+\tau H(\pi_i)
\right]-\frac{\lambda}{2}\|W\|_F^2,
\qquad H(\pi_i)=-\sum_a\pi_{ia}\log\pi_{ia}.
$$

固定 $\tau=0.01$、$\lambda=0.03$；偏置不施加 L2 正则。令 $\bar r_i=\sum_a\pi_{ia}r_{ia}$，则对单题 logit 的梯度为：

$$
g_{ia}=\pi_{ia}\left[r_{ia}-\bar r_i
-\tau\bigl(\log\pi_{ia}+H(\pi_i)\bigr)\right].
$$

$$
\nabla_WJ=\frac1N\sum_i x_i g_i^\top-\lambda W,
\qquad
\nabla_bJ=\frac1N\sum_i g_i.
$$

使用学习率 $0.2$ 的全批量梯度上升，每轮固定 400 步。因为完整奖励矩阵已实际观测，可以直接求经验期望目标的解析梯度，无需对动作做 Monte Carlo 采样。因此本次是**全信息精确期望梯度**，不是采样 REINFORCE 实验。“精确”仅指给定缓存奖励矩阵时的梯度计算，并不表示已经精确知道模型对每道题的真实成功概率。

这一目标一般不是参数上的凹函数，也不保证梯度迭代一定找到全局最优。部署规则为 $a_i=\arg\max_a\pi_\theta(a\mid x_i)$。平滑目标改善并不自动意味着 argmax 路由改善，因此验证门控和最终测试都直接评估 argmax 路由的真实指标。

## 4. 增量自改进循环与接纳规则

初始 Harness 固定使用 `reason`。四轮各新增 32 道训练题，累计训练样本数为 32、64、96、128：

1. 对新一批训练题采集三条路线的真实输出与成本。
2. 将新反馈加入历史记录，构成累计全动作奖励矩阵。
3. 复制当前已接纳的策略，在累计训练数据上进行 400 步梯度上升。
4. 在固定验证集上，使用候选的 argmax 路由评估准确率与效用。
5. 满足接纳条件时替换现任；否则保存候选供审计，现任保持不变。

效用须比现任高出至少 $10^{-6}$。准确率同时满足：

$$
\operatorname{Acc}_{val}(\text{candidate})\ge
\max\left\{\operatorname{Acc}_{val}(\text{initial}),
\operatorname{Acc}_{val}(\text{incumbent})\right\}-0.03.
$$

这既限制相对现任的单次下降，也限制相对初始版本的累计下降；它不构成对真实总体准确率的统计非劣保证。在 48 题验证集上，下降一题约为 2.08 个百分点，下降两题约为 4.17 个百分点。门控允许一定质量与成本权衡，而不是要求准确率绝对不降。

重复使用同一验证集进行四次接纳会产生自适应选择，因此不能把每一轮验证收益当作独立显著性证据。最终结论必须来自冻结后的独立测试集。

## 5. 数据、预算与冻结协议

使用原始 GSM8K 数据。训练和验证从官方训练集抽取，最终测试从官方测试集抽取；按题目规范化文本哈希去重，并排除官方训练集与测试集间的重复题。抽样种子固定为 42，不根据答案、难度或模型成绩筛选题目。

| 划分 | 题数 | 用途 | 无重试时实际请求 |
| --- | ---: | --- | ---: |
| Train | 128 | 四轮梯度更新 | 384 |
| Validation | 48 | 接纳候选、选择固定基线 | 144 |
| Test | 128 | 冻结后的最终评测 | 384 |
| 合计 | 304 | 三条路线完整反馈 | 912 |

本次实验进程的请求尝试上限为 980；与用户总计不超过 1000 次请求的限制之间保留用于前置接口检查的空间。失败重试也应计入请求尝试预算。912 次是无失败、无重试时的预期数，不能承诺恰好只调用 912 次。温度固定为 0，每次最大输出长度固定为 2048。

配置文件记录超参数、提示词所在实现文件的 SHA-256、原始数据 SHA-256 和数据划分。四轮结束后，先保存最终策略、已选版本、最佳固定路线及配置哈希，再开始请求测试题输出。已有冻结策略与重新计算的策略不一致时拒绝复用测试结果。测试题答案只进入评测器，不能用于调整特征、成本权重、提示词、轮数或选种子。

本文件在真实实验已启动、最终测试结果未知时整理；它是对冻结配置的书面记录，不宣称是外部注册平台上的正式预注册。

## 6. 基线、主指标与统计

主要比较为：**学习路由器减去验证集选出的最佳固定路线**。最佳固定路线按照同一成本效用在验证集选择，不能在测试集上挑出最佳固定路线后再宣称公平的模型选择。

同时报告以下辅助比较：

- 初始 `reason`，用于评估自改进相对起点的变化。
- 固定 `direct`、固定 `reason`、固定 `review`，用于解释质量与成本。
- 均匀随机选择三条路线的期望指标；这是基于真实动作结果计算的期望，不是额外执行的一次随机部署轨迹。
- 逐题事后选择最大效用动作的 Oracle，仅作为“已观测三条路线”的不可部署上界。

主要指标为测试集平均效用，附准确率、平均 token、平均请求数、平均路线调用耗时及各路线被选择的题数。初始策略本身等同于固定 `reason`，二者不是两条独立基线。

在同一批 128 道测试题上，逐题计算学习策略与基线的准确性差、token 差和效用差。使用 5000 次按任务配对 bootstrap，报告点估计与 95% 百分位区间。每次重采样对两种策略使用同一组题目索引，保留同题及共享初稿带来的相关性。每个区间是边际区间，不代表所有指标同时成立的 95% 保证。

这些区间描述固定模型输出和固定已训练策略下的任务采样不确定性，不包含服务端随机性、训练集重新抽样、不同优化种子或模型升级带来的变化。每道题每条路线只有一次观测，温度为 0 也不保证远程服务完全确定。128 道测试题仍属于小规模 benchmark，准确率改变一题约为 0.78 个百分点；不应声称已经证明跨模型、跨任务的普遍优势。

## 7. 成本公平与解释性分析

实际采集成本和假想部署成本分别统计：

- 实际采集成本依据请求日志计算，包含为了学习和评测而执行的全部路线。已失败请求如果供应商仍收费、但没有返回 usage，其费用无法从现有日志精确恢复，需如实标记。
- 部署成本是假设只执行选中路线时的成本，`review` 必须包含两步。不能把复用初稿节省的采集请求数冒充部署请求数。
- 输入与输出 token 分别保留；若未来知道真实单价，可另做明确标注的费用估算，不能事后更改本次主目标。
- 路线耗时由 API 调用耗时累计，含网络与服务端调度影响。当前 `wall_seconds` 计时起点在验证数据采集完成之后，不能作为完整实验总耗时。

若学习路由器相对基线每题节省 token，可用“训练与探索总 token / 单题部署 token 节省”估计 token 层面的摊销任务量，并明确使用哪些开销作为分子；这不等于本次小样本实验已经回本。

针对 `review` 单独统计：初稿错误而复核正确的题数、初稿正确而复核错误的题数。准确率净变化应与“修好减改错”一致；即使净准确率提高，也应结合额外 token 判断固定复核是否值得。

## 8. 结果解释与失败条件

实验不保证取得正向收益。报告遵循以下规则：

| 观察结果 | 可支持的表述 |
| --- | --- |
| 相对最佳固定路线的效用差为正且配对区间下界大于零 | 在本次模型、任务样本、输出缓存和成本定义下获得正向证据 |
| 效用点估计为正但区间跨零 | 存在探索性改善趋势，统计证据不足 |
| 相对初始 `reason` 改善，但不优于最佳固定路线 | 自动选择改善了初始配置，尚未证明上下文路由优于选对固定流程 |
| 更省 token，但准确率下降 | 报告明确的质量与成本权衡，不称为无损能力提升 |
| 候选全部未被接纳 | 门控完成保护作用，但本设定没有实现可部署改进 |
| 最终策略几乎固定选择一个动作 | 可能自动发现了更合适的固定流程，不能夸大为强任务自适应 |
| Oracle 与最佳固定路线差距很小 | 在已观测动作与题目上缺少路由改进空间 |
| Oracle 优势较大，学习路由没有优势 | 当前特征、数据量或优化过程未能充分预测路线差异 |

不删除不利题目，不选最好种子充当主结论，不根据测试结果改变阈值或提示词。失败同样可以形成完整作业：给出机制、实现、严谨对比和失败原因，比仅展示训练奖励上升更有说服力。

## 9. 相关工作与本项目定位

以下四篇论文的标题与摘要已从 arXiv 页面核验，页面存于 `data/raw/`，元信息见 `docs/source_verification.json`。本项目未声称复现它们的完整实验，也不复述未核验的论文细节。

1. **TextGrad: Automatic "Differentiation" via Text**，arXiv:2406.07496。[原文](https://arxiv.org/abs/2406.07496)。其摘要描述由 LLM 提供并反向传播文本反馈，用于改进复合系统组件。这里的“文本梯度”是自然语言优化反馈，并不是对实值参数求出的严格数值导数。本项目选择 softmax 参数的解析梯度，便于最优化课程进行公式推导和数值验证。
2. **Automated Design of Agentic Systems**，arXiv:2408.08435。[原文](https://arxiv.org/abs/2408.08435)。其摘要提出由元智能体编写代理代码，并利用已有设计档案逐步发现新系统。本项目将可变空间限制为固定流程间的路由参数，以适应少量调用与短周期。
3. **GEPA: Reflective Prompt Evolution Can Outperform Reinforcement Learning**，arXiv:2507.19457。[原文](https://arxiv.org/abs/2507.19457)。其摘要描述利用轨迹反思、提示词更新与 Pareto 思想进行提示词优化。[作者公开代码](https://github.com/gepa-ai/gepa)。本项目从中借鉴评测驱动改进的研究问题，但使用固定提示词和数值参数梯度，并不以 GEPA 为已经运行的对比基线。
4. **Darwin Godel Machine: Open-Ended Evolution of Self-Improving Agents**，arXiv:2505.22954。[原文](https://arxiv.org/abs/2505.22954)。其摘要描述修改自身代码、使用编码 benchmark 验证变化并维护代理档案。本项目只有参数更新与版本接纳，不具备该论文所讨论的开放式代码自我修改能力。

GSM8K 原始数据与任务说明：[openai/grade-school-math](https://github.com/openai/grade-school-math)。本实验使用其公开数据和自行实现的轻量 Harness；这些论文属于定位与设计参考，不等于工程建立在它们的代码实现上。

## 10. 几天内的交付范围

第一阶段完成数据、三条固定路线、缓存和请求账本；第二阶段完成解析梯度、有限差分检查、预算检查及自改进门控；第三阶段完成真实采集、冻结测试、配对统计与报告。CPU 只承担文本特征、48 个参数的优化和结果统计，无需 GPU 或训练基础模型。

最终交付应包含可运行代码、冻结配置及数据哈希、请求与输出缓存、各轮候选和接纳记录、最终冻结策略、独立测试结果及如实解释正负结果的 benchmark 报告。
